# Plan: Conform bookmark-organizer to code.md and plan.md

## Problem Statement

The `bookmark-organizer` project is missing the planning collateral required by `plan.md` (no `plans/` directory, no plan file). Additionally, a review against `code.md` and project conventions reveals several conformance gaps:

1. **Lint failures** — `ruff` reports deprecated `typing` imports, unused imports, unsorted `__all__`, and import sorting issues across `src/` and `tests/`.
2. **Type-check failures** — `mypy` fails because `python_version = "3.9"` is no longer supported by the installed mypy, and there are type mismatches in `cli.py` (duplicate link/folder groups are swapped in assignments).
3. **CI gaps** — The GitHub Actions workflow does not validate the install script and does not pin action versions to commit SHAs as required by `AGENTS.md`.
4. **Repository hygiene** — Generated artifacts (`src/bookmark_organizer.egg-info/`) are committed, and there is no `.gitignore` to exclude build artifacts, caches, and virtual environments.
5. **Planning debt** — No `plans/` directory or plan document exists, violating `plan.md` rule 8.

## Design

Fix the issues in four focused phases so each change is small, testable, and reviewable.

### Phase 1 — Repository Hygiene
- Add a `.gitignore` for Python projects (`.venv`, `__pycache__`, caches, `*.egg-info`, etc.).
- Remove committed generated artifacts (`src/bookmark_organizer.egg-info/`).

### Phase 2 — Lint & Type Fixes
- Modernize type annotations (`list`/`tuple`/`X | None` instead of deprecated `typing` aliases) where the project already uses `from __future__ import annotations`.
- Remove unused imports and sort `__all__` and import blocks.
- Fix the type mismatch in `cli.py` where duplicate folder groups are assigned to a variable typed as duplicate link groups.
- Update `pyproject.toml` to set `mypy` `python_version = "3.10"` and bump `requires-python` to `>=3.10` to match the installed toolchain.

### Phase 3 — CI Hardening
- Pin all GitHub Actions to commit SHAs.
- Add a step to validate the install script (`bash -n install.sh` and a dry-run invocation).
- Ensure `pull_request` is used (already correct) and permissions remain minimal.

### Phase 4 — Planning Collateral
- Create `plans/` directory.
- Write this plan file and any follow-up plans there.

## Architecture

No runtime architecture changes. All changes are to development tooling, CI configuration, and repository metadata. The CLI, parser, dedup, and cleanup modules remain functionally unchanged except for type-annotation cleanups.

## Risks & Alternatives

- **Risk:** Bumping `requires-python` to `>=3.10` could block users on 3.9.
  - **Alternative:** Keep `requires-python = ">=3.9"` and downgrade `mypy` to a version that still supports 3.9, or pin `mypy` to `<1.14`. However, modern dependency management (uv) and the existing `target-version = "py39"` in ruff suggest 3.9 is the floor; mypy 1.19.1 is already specified and does not support 3.9, so aligning to 3.10 is the cleaner fix.
- **Risk:** Removing `egg-info` from the repo may break someone who expects it to be present.
  - **Alternative:** Add it to `.gitignore` and purge it from the index; this is standard Python practice.
